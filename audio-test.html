Web Audio control test

None of the lo-fi engine is on this page. Each test is the simplest thing that makes a sound at that layer, so whichever one crackles tells you where the fault is. Listen to each for ten seconds or so.

1 · plain audio element A looping tone through <audio>, not Web Audio at all. Crackles here too → the fault is the device or browser's audio output generally, nothing to do with Web Audio.
2 · bare web audio oscillator One OscillatorNode straight to the destination. No library, four lines of code. Clean in 1 but crackles here → Web Audio itself is failing on this browser and device. That is a Firefox bug, not an app bug.
3 · web audio, a few nodes Oscillator, gain, filter and a little polyphony — still no library. Clean in 2 but crackles here → it copes with a trivial graph and not a modest one, which points at CPU headroom.
4 · a new node per note Four notes a second, each one a brand new oscillator that is started and then stopped — which is exactly how a synth voice works, and what the lo-fi engine does ~26 times a bar. Crackles here → the fault is the cost or handling of starting and stopping nodes, not the sound itself.
5 · same notes, no new nodes Identical rhythm and pitches, but one permanent oscillator whose volume is faded up and down. Same music, no node churn. Clean here while 4 crackles → that is the answer, and it is fixable: the engine can hold a pool of permanent voices instead of building one per note.
